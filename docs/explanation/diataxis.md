# Diátaxis 4분류 개요

이 문서 사이트는 Diátaxis 프레임워크를 따라 문서를 네 종류로 나눕니다. 왜 이렇게 나누는지, 각 문서가 어느 좌표에 있는지 설명합니다.

## 두 개의 축

Diátaxis는 문서를 두 축으로 배치합니다.

- 첫째 축은 **실행(do)**과 **이해(know)**입니다. 독자가 무언가를 하려는가, 아니면 알려는가를 구분합니다.
- 둘째 축은 **학습(learning)**과 **작업 수행(working)**입니다. 독자가 처음 배우는 중인가, 아니면 이미 알고 결과를 얻으려는가를 구분합니다.

| | 학습 | 작업 수행 |
| --- | --- | --- |
| 실행 | 튜토리얼 | how-to |
| 이해 | 설명 | 레퍼런스 |

## 네 종류의 역할

**튜토리얼**은 초보자가 하나의 결과를 만들어 보는 수업입니다. 성공 경로만 따라가며 옵션이나 예외, 원리 설명은 뒤로 미룹니다. [개발 환경 시작하기](../tutorials/getting-started.md)가 여기에 해당합니다.

**how-to**는 이미 기본을 아는 독자가 특정 목표를 끝내는 레시피입니다. 목표 하나, 전제 조건 한 줄, 최소 단계, 성공 확인으로 구성됩니다. [기여하기](../how-to/contributing.md)가 이 모드입니다.

**레퍼런스**는 구성 요소를 정확하고 건조하게 기술한 사전입니다. 의견이나 서사 없이 이름, 기본값, 설명, 예시를 일관된 형식으로 나열합니다. [CLI와 설정](../reference/cli-and-configuration.md)이 여기에 속합니다.

**설명**은 맥락과 의미를 다루는 논의입니다. 행동 방법이 아니라 왜 그렇게 되었는지, 어떤 대안과 트레이드오프가 있었는지를 풀어 씁니다. [git 훅과 `--hook-command`](hook-command.md)와 이 문서가 설명에 해당합니다.

## 한 문서에 한 모드

같은 문서 안에서 모드를 섞으면 독자가 헷갈립니다. 튜토리얼 중간에 레퍼런스 표가 나오면 수업의 흐름이 끊기고, how-to에 원리 설명이 길어지면 목표까지의 거리가 멀어집니다. 그래서 이 사이트에서는 한 문서에 한 모드만 적용하고, 다른 목적은 링크로 분리합니다.

예를 들어 튜토리얼에서는 `mise run setup`을 실행하라고만 하고 왜 `--hook-command`가 필요한지는 설명하지 않은 대신 [git 훅과 `--hook-command`](hook-command.md)로 연결합니다. 이런 분리 덕분에 각각의 문서가 짧게 목적을 유지합니다.
